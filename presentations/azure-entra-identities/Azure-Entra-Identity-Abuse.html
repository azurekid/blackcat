MENTAL MODEL

Acquire -> authenticate -> authorize -> act

01

Acquire

A password, application credential, bearer token, workload execution path, or trusted workflow.

02

Authenticate

A token is issued for a particular audience; a Graph token is not automatically an ARM token.

03

Authorize

The resource checks permissions and scope. Authentication success does not guarantee access.

A signed token can be valid while its use is malicious.
AZUREHACKING / 2026-11-09[FIC] [GRAPH] [MITRE]04 / 43
Speaker notes / 1 min Expand Azure Resource Manager (ARM), OAuth 2.0, and OpenID Connect (OIDC). A bearer access token can be usable by its holder until expiry or applicable revocation enforcement; do not imply that all tokens can be replayed, renewed indefinitely, or used at every API. DETECTION / MICROSOFT SENTINEL

Hunt for changes that create authority

AuditLogs
| where TimeGenerated > ago(24h)
| where OperationName has_any
    ("credential", "consent", "permission", "role")
    or OperationName =~ "Update application"
| extend ActorUser = tostring(InitiatedBy.user.id),
         ActorApp = tostring(InitiatedBy.app.servicePrincipalId)
| mv-expand Target = TargetResources
| project TimeGenerated, OperationName, Result,
          ActorUser, ActorApp,
          TargetId = tostring(Target.id),
          TargetName = tostring(Target.displayName)
| order by TimeGenerated desc
Broad hunt, not a production-ready analytic. Tune from actual tenant events.
